# 파일럿 절차 — 관문 순서대로

배포 전에 한 계정에서 10분. 각 단계가 무엇을 증명하는지가 적혀 있으니, 막힌 단계의 문구만 있으면 원인이 갈린다.

## 0. 전제

- 업로드하는 계정이 조직의 **소유자(Owner)**여야 한다. 관리자(Admin)는 「조직 설정 → 플러그인」이 안 보인다
- 시험할 PC에 `node -v`, `python --version` 둘 다 나와야 한다
- **사람이 직접 올린다.** 다른 Claude 세션에 "이걸 설치해서 시험해줘"라고 시키면 그 Claude가 자기 버전을 새로 만든다 (실제 사례)

## 1. 업로드 → 서버가 뜨는가

조직 설정 → 플러그인 → 플러그인 추가 → 파일 업로드 → ZIP. 상태는 「기본 설치」(혼자인 조직) 또는 「설치 가능」+본인 설치. 데스크톱 앱 재시작.

Cowork 새 작업(폴더 아무거나) → 붙여넣기:
```
사용할 수 있는 도구 이름을 전부 나열해줘. fetch_lite, read_lite, run_quiet, checkpoint_verify 가 있는지 알려줘.
```
- 4개가 (긴 접두어와 함께) 보임 → 2로
- 안 보임 → 앱 로그 `%LOCALAPPDATA%\Claude\Logs\main.log`에서 `lite-tools` 검색. `Connected … (4 tools)`가 없으면 서버 기동 실패(대개 node 없음)

## 2. 웹 읽기가 되는가

```
fetch_lite 로 (기사 URL) 를 읽고 요지 두 줄과 돌려받은 글자 수를 알려줘.
```
- 기대: 수백~2,500자. 기존 도구였다면 수만~십수만 자
- `가져오기 실패` → 사이트가 차단하거나 JS 렌더링 페이지. 다른 URL로

## 3. 체크포인트 + 세션 안 검증

```
방금 읽은 기사에서 사실 5개를 뽑아 체크포인트를 쓰고, checkpoint_verify 를 돌려서 결과를 그대로 보여줘.
```
- 기대: `검사 5건 / ✗ 0건 / 수동확인 0건` 이 **세션 안에서** 출력
- `읽기 실패 … ENOENT` → 경로 매핑 실패. 폴더가 Cowork 마운트 기록에 없는 경우. 이슈로

## 4. 검증기가 틀린 걸 잡는가

```
체크포인트 사실 표 첫 행의 출처 행 번호를 99행으로 바꾸고 다시 checkpoint_verify 를 돌려줘.
```
- 기대: `✗ …: 인용은 N행에 있음 - 출처는 '99행'으로 적힘`

## 5. 다른 PC에서 1~3 반복

조직 배포의 핵심 검증. 다른 PC·같은 조직 계정에서 3까지 통과하면 배포 가능.
