# 경량 모드 (v0.2)

## 0. 도구 이름

lite 도구 4개는 플러그인 경유라 **긴 이름**으로 보인다. 짧은 이름으로 찾으면 "일치 없음"이 난다.
- `…lite_tools__fetch_lite` · `…lite_tools__read_lite` · `…lite_tools__run_quiet` · `…lite_tools__checkpoint_verify`
- 도구 목록에서 `lite_tools__` 가 들어간 이름을 그대로 쓴다.
- 경로는 **Cowork에 보이는 그대로** 넘긴다 (`outputs/체크포인트.md`, `/sessions/…/mnt/폴더/…` 둘 다 됨). 도구가 사용자 PC 경로로 바꿔 읽는다.
- 이 도구들은 사용자 PC에서 실행된다. PC 연결이 끊기면 목록에서 사라진다.

## 1. 읽기 규칙 (항상)

| 하려는 것 | 쓰지 말 것 | 대신 쓸 것 |
|---|---|---|
| 웹페이지 읽기 | `web_fetch` / `WebFetch` | `fetch_lite(url, grep="키워드,키워드")` — 원문 그대로라 인용이 성립한다 |
| **30~200KB 파일** | `Read` 통째 | `bash: grep -n "키워드" 파일` 로 행 번호 → `Read` 에 `offset`/`limit`, 또는 `read_lite(path, grep=…)` |
| 200KB 넘는 파일 | (모델이 알아서 grep 함) | 위와 같음. 통째 읽기는 어차피 불가 |
| 설치·빌드·테스트·출력 긴 명령 | `bash` 원출력 | `run_quiet(cmd, cwd)` 또는 `cmd 2>&1 \| tail -30` |
| 검색 | 결과 전부 열기 | 상위 3건만 `fetch_lite`로 |

- **위험 구간은 큰 파일이 아니라 중간 크기(30~200KB)다.** 작으면 통째로 읽고 커지면 알아서 grep 하지만, 중간 크기는 통째로 읽어 버린다. 이 구간에서 반드시 grep 먼저.
- `fetch_lite`가 `[실패 - JS 렌더링 페이지]`를 돌려줄 때만 `WebFetch`를 쓴다. 그 결과는 원문이 아니라 모델이 다시 쓴 텍스트다 — 인용하지 말고 요지만 취한다.
- 같은 페이지·파일을 두 번 읽지 않는다. 필요한 값은 처음 읽을 때 적어 둔다.
- 읽은 결과를 답변에 통째로 옮겨 적지 않는다.

## 2. 서브에이전트 위임 — 조건부

위임은 **고정비가 약 4만 토큰**이다(실측). 원문이 그보다 훨씬 클 때만 이득이다.
- 위임할 때: 웹페이지 **5건 이상** 조사, 200KB 넘는 로그·코드 탐색에서 결론만 필요할 때
- 위임하지 않을 때: 파일 1~3개 조회, 값 몇 개 찾기 — 직접 grep이 항상 싸다
- 위임 지시문에는 ① 돌려줄 항목을 번호로 ② "본문을 옮겨 적지 마라" ③ "인용은 원문 그대로 40자 이내" ④ "실패하면 실패 문구를 그대로 적어라"

## 3. 체크포인트 — 언제

- 툴 호출이 **30회를 넘겼고**, 지금 하는 **하위 작업이 끝난 시점**에 쓴다. 작업 중간에 끊지 않는다.
- 파일: `outputs/체크포인트.md` (이미 있으면 덮어쓴다)
- 웹에서 인용할 값이 있으면 `fetch_lite` 결과를 `outputs/원문_<이름>.txt`로 저장하고 **그 파일을 출처로** 적는다. URL은 인용 대조가 안 된다.
- 쓴 뒤 반드시 `checkpoint_verify("outputs/체크포인트.md")`를 실행한다.
  - ✗ 가 하나라도 있으면 그 줄을 고치고 다시 실행한다. 인용을 지어내지 말고 원문을 다시 읽는다.
  - 행 번호 불일치는 검증기가 실제 행을 알려준다. 그 값으로 고친다.
  - ✗ 0건이 되면 사용자에게 알린다: **"여기까지 체크포인트에 정리했습니다. 새 작업으로 시작하시면 이어서 진행합니다."**

## 4. 체크포인트 — 양식 (이 형식 그대로)

```markdown
# 체크포인트 — YYYY-MM-DD HH:MM

## 목표
(사용자가 요청한 것. 1~3줄)

## 사실 표 — 원문 그대로, 출처 필수
| 항목 | 원문 인용 | 출처 | 상태 |
|---|---|---|---|
| 계약금 | "계약금은 540만 원(부가세 별도)으로 한다" | 계약서_v3.docx 12행 | 확인 |
| 화재 신고 | "오후 10시 29분께 … 신고가 접수됐다" | 원문_etoday.txt 8행 | 확인 |
| 담당 | "김OO 부장" | 대화 | 추정 |

## 결정한 것
- (한 줄씩)

## 진행 상황
- 완료: … (산출물 경로)
- 진행 중: …
- 다음: …

## 원문 위치 (요약하지 않음)
- 계약서_v3.docx — 12~40행: 대금 조건
- outputs/원문_etoday.txt — 6~23행 (fetch_lite 발췌, 원본 URL: …)
```

## 5. 체크포인트 — 규칙

**사실 표**
- 인용은 따옴표 안에 **원문 그대로**. 의역·반올림·단위 변경·요약 금지. 길면 자르되 바꾸지 않는다. 따옴표 없는 행은 ✗.
- 항목명은 그 인용이 실제로 받치는 것만 적는다. 발화를 인용해 놓고 항목명에 그 발화의 결과를 적지 않는다.
- 출처는 `파일명 12행` 또는 `파일명 12~40행`. **행 번호는 `grep -n`으로 확인한 값**을 적는다 — 기억으로 적지 않는다. 검증기가 행까지 대조한다.
- 출처 없는 사실은 쓸 수 없다. 대화에서 나온 것은 출처 `대화`, 상태 `추정`.
- **웹 출처(URL)는 상태가 무조건 `추정`.** `확인`으로 올리려면 `fetch_lite` 원문을 파일로 저장해 그 파일을 출처로 적는다.
- 상태는 `확인`(출처 파일에서 원문을 봤음) / `추정` 둘 중 하나.
- 사실 표는 크기 제한이 없다.

**원문 위치** — 디스크·웹의 원문은 요약하지 않는다. 파일명·행 범위·URL·키워드만 남기고, 다음 세션에서 `read_lite` / `fetch_lite --grep`으로 그 부분만 다시 읽는다.

**서사(목표·결정·진행)** — 짧게. 28,000자를 넘기지 않는다. 사실 표와 다르면 **사실 표가 우선**.

## 6. 새 세션을 시작할 때

`outputs/체크포인트.md`가 있으면 **먼저 읽는다.** 사실 표를 기준으로 이어가고 서사는 참고만 한다. 체크포인트에 없는 값이 필요하면 "원문 위치"에서 그 부분만 다시 읽는다 — 기억으로 채우지 않는다.
